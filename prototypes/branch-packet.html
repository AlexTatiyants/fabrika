It teaches the setup page to finish on a Linux server with no screen. D-1

Fix a refused npm install by moving npm's global prefix to ~/.local for the whole account

The button doesn't install into a folder of Fabrika's own. It runs npm config set prefix ~/.local, which writes ~/.npmrc. From then on, every npm i -g on this account, for any program, lands in ~/.local.

needs you

What else it touches

  • Packages already in /usr/local still run, but npm ls -g and npm update -g stop seeing them.
  • The prefix is set before the install runs and stays if the install then fails. See F-1.

Not taken

  • npm i -g --prefix ~/.local … for this one command, leaving ~/.npmrc alone.
  • A folder of Fabrika's own, put on the PATH of the process it starts.

Undo

Easy: npm config delete prefix. The card states the change before the button is pressed ("Nothing outside your home folder changes").

F-1

A failed install leaves npm's prefix moved anyway

minorbreaker · confirmed by reading the code

"Install there" sets the prefix, then runs the install. If the install fails for another reason (no network, a registry error), ~/.npmrc has still been changed, and the error shown is npm's. It doesn't mention the change it just made.

factory/commissioning.py · install_route · see it in the code 228 if npm_user_prefix: 231 prefix = ["npm", "config", "set", "prefix", str(NPM_USER_PREFIX)] 232 code, out = await _run(prefix, 60) 235 code, out = await _run(argv, 600) # a failure here keeps the prefix
related to D-1
F-2

For a system-wide service, the PATH fix names the wrong systemd

minorreviewer

systemd sets INVOCATION_ID for system units and user units alike. The remedy always says systemctl --user daemon-reload, which reloads the wrong manager when Fabrika runs as a system service. The suggested Environment=PATH=… line also copies in the whole of the current PATH, so later changes to the unit's PATH are lost.

factory/commissioning.py · _path_remedy · see it in the code 285 if os.environ.get("INVOCATION_ID"): 288 return {"text": "… then run `systemctl --user daemon-reload` and restart it.", 289 "command": f"Environment=PATH={folder}:{os.environ.get('PATH', '')}"}
the test sets INVOCATION_ID only, so it can't tell the two kinds of unit apart
F-3

A blank token sent to the API erases the stored one and reports "Token saved"

nitbreaker · reachable only by calling the API directly

The body only requires one character, so " " is accepted. It is stripped to empty, and write_credential treats empty as "remove". The stored token is deleted, and the reply says it was saved. The card trims before sending, so nobody using the page can reach this.

factory/server/setup.py · put_token  ·  factory/config.py · write_credential · see it in the code write_credential(cfg, route.token_env, body.token.strip()) return {"ok": True, "detail": "Token saved beside factory.yaml, owner-only."}
no test sends a blank token
