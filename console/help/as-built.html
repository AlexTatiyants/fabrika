The as-built is a plain-language account of your codebase as it stands: what it is, how its parts fit together, and what it does. It's read from every file, so you can learn a repository cold, or check it before reviewing a feature.

How it's made

Fabrika reads each file once. Small files go up to ten to a call, large ones alone and in parts, on the model the crew page gives the reader. What the reader reports is checked against the code: a function counts only if it is at the line it was given, and a link between files is confirmed only where the code makes it. Numbers and links are computed from the repository. Names and summaries are written by a model from what each file contains.

Where it lives

It's committed to your repository, under .fabrika/as-built/, so anyone can read it there without Fabrika. It records the commit it describes. Fabrika never edits your own files, and that folder is ignored when deciding whether the reading is current.

Reading it again

The button in the header says what it will do: Read the repository the first time, Refresh when your code has moved on, Read again when nothing has. After the first reading, only the files that changed since are read. The header shows Out of date when the checked-out commit is ahead of the reading; press it to see which files changed.

  • A reading on a plan with usage windows pauses itself before the window is full, and keeps what it read. Carry on reading reads only what's left.
  • If the as-built folder has edits that aren't committed, a new reading won't start until you commit or discard them.
  • A reading runs on the server, so you can leave the page while it works.

The pages

  • Overview: the summary, six tiles (subsystems, capabilities, code, tests, links, coverage), what's worth knowing, where to start reading, and the files nearly everything uses. Coverage says how many files were read and what wasn't: dependencies, build output, binaries, and anything that couldn't be read. Tests is the share of the code that some test imports or calls, not a coverage tool's number.
  • Architecture: what runs where. See Architecture.
  • System: the parts, and what depends on what. See The system map.
  • Capabilities: what a person can do with it. See Capabilities.

How far to trust it

A dashed link, or one marked reported, not confirmed, is one the reader said it saw and the code didn't prove. Treat it as a lead. Generated files are marked: they're read for the picture, not for review.
