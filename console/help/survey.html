The survey is Fabrika reading your repository to learn how it's built and tested, so every feature is checked the way your project already checks itself.

What it reads

Your manifests, config, scripts and CI, and a sample of your tests. From them it works out what the project is, what it's built with, which commands your repository already runs as checks, how its tests are run at each level, how they clean up, and what a container for it needs.

What it proposes

  • Checks: the commands every feature is held to. See Checks.
  • How tests run, level by level. See Test levels.
  • An environment to run it all in. See The environment.
  • Suggestions: tools or helpers your repository would benefit from. None of them blocks anything; each is yours to take or turn down.

Nothing changes without you: the first survey is accepted on the project page, and every later one arrives as a proposal you rule on, item by item.

When to re-survey

After your tooling changes: a new test runner, a new service, a fix you made with your coding agent. The Survey tab says when files it reads have moved since the last reading. The survey reads your last commit, so commit first.
