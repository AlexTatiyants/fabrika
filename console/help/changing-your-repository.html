Some fixes Fabrika applies itself, with your OK. Others need a change to your code, and for those Fabrika gives you a prompt to hand to your coding agent.

What Fabrika can apply

  • A setting: how a check is run, where a test file goes, what runs before the checks.
  • A support file: a setup file your test runner already loads, or a helper new tests can import. Fabrika writes it into your repository and commits it. It never writes a test itself: a test Fabrika wrote and then passed would prove nothing.
  • An environment step: a command that puts data back before the checks run.

You pick one fix per test level, on that level's card on the Tests tab (press Apply) or in a re-survey's proposal, and Fabrika applies it whole, in the order its parts need.

What needs your coding agent

Some fixes need real code: an endpoint that lets a test create or delete its own data, or a way to open the app on a workspace of the test's choosing. Fabrika won't build these as features. Its own runs need the testing to work before they can check anything, so building the testing through one of them goes in a circle.

Instead, the fix comes with a prompt. Copy the prompt, give it to your coding agent, review and commit the change, then press Resurvey on the project page. The survey reads your last commit, so commit first.

If you'd rather not

For a level with no cleanup, choose Don't check criteria at this level; the choice is recorded and the page stops asking. Fabrika keeps building features; criteria at a level it can't test cleanly are handed to you instead. See When a level isn't checked.
