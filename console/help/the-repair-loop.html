When the review finds something fixable, Fabrika tries to fix it itself, in rounds, inside limits set in factory.yaml. From your calls, you can send more to the same loop.

How a round works

The arbiter routes each finding. Those routed for repair go to repairers, which run in parallel, each fixing one named defect and nothing else on the way past. Then the line runs again over the repaired code, and each finding is marked repaired, still standing, or no longer holding. A repairer can't touch the blind tests or the breaker's probes; a fix that belongs in a blind test goes to the oracle instead. When the loop is done, the simplifier removes what's correct but written twice, a last full review runs, and the rapporteur writes the packet.

What bounds it

Every stopping condition is a number a person wrote down, read by code and never by a model:

  • rework.max_rounds: two by default. Needing a third usually means the loop has stopped fixing the code and started arguing with the reviewer.
  • rework.max_attempts_per_finding: a finding tried twice and still there comes to you, with what was tried.
  • rework.budget_usd: the money the loop may spend, counted over the feature's whole life, less a reserve kept back so a packet can always be produced. Verifying again, building again or sending it round again doesn't buy more.
  • rework.wall_clock_minutes, and the usage window of any plan the run is on.

The budget is in dollars, and an agent on a subscription reports turns, not dollars, so the budget can't stop it. When that happened, Stats says so.

Sending your own

Calls you tag repair go to the same loop: Send to the repair loop resumes the build against the same spec, reusing the plan, the blind tests and the work already merged, with your notes as the objectives. Once the budget is spent the button is disabled, and the card says what's left and that raising rework.budget_usd is how to buy another round.

The Repairs tab

One row per round, opening onto the units it sent out: the file, what the diff does, the findings it closed, and the choices it made. The last row is why the loop stopped. A loop that converged and a loop that ran out of rounds mean opposite things.
