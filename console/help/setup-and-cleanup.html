Every test has to leave things as it found them, so the next test starts from the same place. The survey reads how your tests do that, level by level.

The four answers

  • Reset for every test. Something resets the data before or after each test whether the test remembers or not: a fixture that recreates the database, a transaction rolled back, a truncate. The strongest answer.
  • Each test uses its own data. Nothing is reset, and nothing needs to be: every test that writes creates its own space first (its own workspace, account or folder) and writes only there. Leftovers pile up, but no test reads another's.
  • Each test undoes its own. Nothing resets the data; the convention is that each test removes what it made. It works while every test remembers. Fabrika's tests follow the same convention.
  • No cleanup. Nothing resets the data and tests don't undo anything. Tests at this level can break each other, so Fabrika doesn't check criteria here until one of the fixes is in.

Unit tests share no data, so cleanup never takes the unit level out; only a missing runner does.

What Fabrika already does for you

Every check session runs in a fresh environment of its own, which is thrown away afterwards, databases included. So nothing a test writes survives into the next run. Cleanup only matters within a run, where all the tests share one environment.

When the survey offers a fix

For a level with no cleanup, one where each test undoes its own, or one where the way tests keep to their own data isn't somewhere a new test can use it, the survey offers fixes. Each is one complete change: a setup file your test runner loads, a helper new tests can import, a reset step, or a prompt for your coding agent. See When Fabrika asks you to change your repository.
