Once you approve the spec, the build runs to the end without you. Watch it or leave: it runs on the server, and the feature comes back awaiting verdict with a review packet.

What runs

  • Build: the architect cuts the spec into units and the plan checker reads the cut; workers build the units in parallel; the integrator joins them and tests the seams between them.
  • Verify, at the same time: the oracle writes acceptance tests from the spec alone, never seeing the code. The two lanes can't see each other.
  • Validate: your project's checks run (checks); code, not an agent, runs the blind tests one file at a time (qa); a check that failed is run again at the commit the feature started from (attribution); the breaker attacks the result and proves each break with a failing test.
  • Review: the review panel reads the change, the arbiter decides what happens to each finding, repairers fix what's routed for repair in bounded rounds, the simplifier removes what's correct but written twice, and the rapporteur assembles the packet.

The line

Under the feature's name is a row of lamps, one per station, grouped spec, build, validate and review. Point at one for what it's doing. White and blinking is working now, green passed downstream, red stopped the line, and dark is waiting (or, on a line that has stopped, not reached). On a finished run, a station that had nothing to do says so. \ folds the lamps into a row of dots.

The rework rail under the lamps says whether the repair loop ran. While it does, the line is labelled First pass or Repair round 1, 2 and so on, and lamps from an earlier pass are dimmed. See Repairs and the repair loop.

The build screen

The build step, and runs beside it, show every run of the feature: a Timeline of what ran when (its clock skips the stretches where nothing was running, mostly waits for you; show wait time puts them back), and the Call Tree, every agent's turn in order, branching where work ran in parallel, with each call it made. The band at the top says what's spent of what's spendable. Every prompt and response, raw, is in the feature's ledger.

When it stops

If a station fails, or the process running the build goes away, the line says it stopped and offers Resume the run, which re-runs only what stopped. See Verify again, build again, resume, discard.
