Guides are the repository's own files that say how its code is written. What's committed on the branch features start from is what binds, for Fabrika's agents and for anything else that writes code there.

What counts

  • How to work here: AGENTS.md at the root (commands, code style, testing), a nested one for a folder's own rules, CLAUDE.md, which is the same thing for Claude Code, and any document an AGENTS.md points to.
  • UX and visual style: DESIGN.md at the root, for anything a person sees.
  • Skills: name/SKILL.md, in .claude/skills/ or .agents/skills/.

How Fabrika uses them

Fabrika stores and approves nothing here. It reads the files at the commit a feature starts from, so the repository says which rules are in force and every tool sees the same set. A coding harness that loads them itself reads them directly; an agent with no harness, such as the scout, the architect, the reviewer or a checker, is handed the same files by code. The oracle and the breaker get only what the guides say about testing. Every worker sees every skill: Fabrika links them, for each session only, into the folder its tool reads.

What it proposes

Fabrika proposes changes to guides as commits you edit first: an AGENTS.md where there is none, a DESIGN.md started from the design tokens the code defines, a CLAUDE.md that points at AGENTS.md, a line pointing AGENTS.md at DESIGN.md, a link so both skills folders hold the same skills, a commit for guide files sitting uncommitted in your working copy, and, once a few features have run, the conventions they kept following that AGENTS.md doesn't state yet. In that last one every rule was counted by code; the sentences are a model's, and yours to edit.

Review opens the text in an editor. Change it if you like, then Commit: exactly what's in the editor is written to your working branch and committed. No thanks declines, and it isn't offered again. Guide files in your working copy that aren't committed are listed first, because until they're on the base branch no agent follows them.

Where the code disagrees

When a feature's scout finds code doing otherwise than a guide says, the tab lists it. Settle each in the guide or in the code. New skills go in whichever skills folder you choose here.
