Fabrika checks each acceptance criterion at the lowest level where it can honestly be checked: unit, integration or user.

Unit

Logic on its own, with no database, network or browser: a function, a class, or a front-end component rendered with made-up data. Fast, and the easiest level to keep clean.

Integration

Your application's own interfaces, the way another program uses them: an HTTP API called with a real database behind it, a queue consumer handed a real message. Most data the tests create lives here, so how they clean up matters most.

User

The whole system, the way a person uses it: a browser driving the real front end against the running back end, or a command line run end to end. The slowest level, and the one where tests most often share data by accident.

How a criterion gets its level

When the spec is written, each criterion is given the lowest level at which it can be checked, and the spec shows it. A criterion at a level this project can't test is still in the spec; it's checked by a person instead. See When a level isn't checked.

What the project page shows

The Tests tab has a card for each level: the runner the survey found, how its tests clean up, and whether it's checked by Fabrika or marked you check. A level with no runner, or whose tests can't clean up after themselves, says why on its card.
