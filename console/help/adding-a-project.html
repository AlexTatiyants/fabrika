A project is a repository, the checks that say whether it's healthy, and the environment those checks run in. You add one from the yard, and nothing is built in it until you accept its checks.

Adding it

On the yard, type the Repository path of a git repository on this machine, a name if you want one, and press Survey it. Nothing in your repository is modified: the surveyor reads it, and the checks run on an untouched checkout.

What accepting needs

What you approve is that the checks work, not that the code is clean. Accept checks stays disabled, and the Checks tab says why, until:

  • every check on the list has run since the list last changed;
  • none of them failed to run at all, such as a tool missing from the environment;
  • at least one passes, so something judges each feature;
  • Fabrika has proved a place in the repository where a blind test, written by an agent that never saw the code, can live and run.

A check that runs and fails doesn't block: fix it, hold it at today's number, or decline it with a reason. See Checks. If the checks run on a Dockerfile the survey wrote, accepting also commits it to your repository as .fabrika/Dockerfile.

On the yard

Each project's lamp is lit by its checks: green when they pass on an untouched checkout, amber when they ran and not all were green, red when they could not run, dark when they haven't been measured. The pill beside it says whether you're needed, such as awaiting you.

When the survey fails

If the reading failed, Survey from scratch. If the reading survived and only the checks after it failed, fix the environment and Try the checks again: surveying again would pay a model to say the same thing.

Once the checks are accepted, the project's main button is Start a feature. See Starting a feature and The project page.
