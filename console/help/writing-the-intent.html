A feature starts as a few sentences in your words: what should exist that doesn't exist now. Nothing is built until you've answered Fabrika's questions and approved the spec it writes from them.

Writing it

On an accepted project, press Start a feature. Write the intent the way you'd say it to a colleague who knows the codebase, give it a Short name (optional), and press Send it to the factory, or ⌘ ↵. Vagueness isn't a shortcut: it comes back as questions, and you answer them either way.

What it starts from

The feature gets a branch and a worktree of its own, cut from the branch the project's features start from, as it is committed. Your own checkout is never written to. If it has uncommitted changes, the screen says so: they won't be in the feature. Tick start anyway, from that branch to go ahead.

What happens next

Two agents read before anything is asked of you. The scout reads the code around the feature and reports what already exists, so nothing is built twice. The interrogator reads your intent against that and writes the questions only you can answer. This takes a few minutes, and runs on the server, so you can leave the page. When it's done the feature is awaiting answers. See The questions.

If the reading is interrupted, Read it again starts it over. Nothing was built, so that costs only the reading.

Looking back

The feature's intent step keeps your words, how the interrogator read them, and any corrections you made. The scout step keeps what the scout found: what not to duplicate, the risks, existing capabilities, where the code contradicts a guide, and the files it thought relevant. See Stages and steps.
