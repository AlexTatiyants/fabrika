Outside work is a branch built somewhere else, in another agent or by another person, and handed to Fabrika to review. It has no spec, so Fabrika works out what the branch does, runs your checks on it, attacks it, and leaves the ending to you: underwrite it or drop it.

Bringing a branch

Open a project's Outside work tab. It lists every branch with commits its base doesn't have. Pick one, say in a sentence what it was for if you like, and press Look at it. The branch is checked out on its own. Nothing on it changes, and neither does your checkout. Each branch is one item, listed under Looked at with the round it's on. Looking at it again starts that item's next round, not a new item.

What a round runs

The stations light on the line at the top of the page, and the packet opens on its Findings tab when the last one is done:

  • The cut: code, not a model, cuts the diff into pieces, so every changed line is in exactly one.
  • Reader: the as-built is read at both ends of the branch, so what it adds can be said in the system's own terms.
  • Checks: the project's approved checks run at the branch's head, in the project's own environment. Where a formatter would rewrite a file, that's recorded and put back. Nothing is committed.
  • Attribution: a check that's red runs again where the branch left its base, to say whether the branch broke it or inherited it.
  • Rapporteur: classes each piece, writes what the branch is, and reads its commits for the claims they make.
  • Breaker, review and arbiter: the attack. See Findings and your calls.

The crew page draws the same line, with the models each agent runs on.

What was built

The branch written up the way a spec would be: what it is, and what it was handed in as. Then:

  • What it adds: components, routes and tables, in the system's terms.
  • Key flows: how the new code runs, end to end.
  • Where it landed: the files by group, then its tests, a list of files, each with the tests it adds. A file's name opens the whole file.
  • What it claims: each claim its commits make, grouped by what stands behind it, worst first. It's broken by a probe, no test exercises it, named by a test that did not run green, or shown by a test. A test's name opens its file at that test.

The code

Every changed line, cut into pieces and classed: novel (a real choice someone has to read, open by default), conventional, mechanical, generated and tests. Each piece says why it was classed the way it was, and a piece the rapporteur was unsure about is classed novel. Order the pieces by materiality or by file. whole file opens the file as it is at the head, with the lines the branch added marked.

Checks

One row per check: passed, failed or couldn't run. A red check says whose it is, from the run at the base. It also says where it fired: on lines the branch wrote, or on lines that were there before.

What happens after the attack, round by round, is in Rounds, fixes and the ending.
