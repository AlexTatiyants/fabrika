A project's page is where you look after the project itself: its checks, how it's tested, its rules, its environment and its history. It opens on an overview of what needs you.

The tabs

  • overview: one line on what's waiting, a tile for each area (amber where something needs you), and the features waiting on you, building and finished.
  • checks: the commands every feature is held to. See Checks.
  • tests: whether Fabrika can test what it builds, level by level. See Test levels.
  • guides: the repository's own rules for how code is written. See Guides.
  • survey: what reading the repository found, and the project's own facts. See The survey.
  • environment: where the checks run. See The environment.
  • as-built: a plain account of the codebase as it stands. See The as-built.
  • history: everything that has happened to the project. See History.

A dot on a tab says something there needs you: a failing check, a proposal waiting, a level waiting on your choice. The project's name, in the bar, leads back to the overview.

The bar

A plate stamps whether the checks are proven (certified, not certified, unproven or out of calibration) and how many of the three test levels Fabrika checks. Beside it, Resurvey has a model read the repository again and propose changes you accept item by item, Run checks runs every check on untouched code, and Start a feature opens the composer once the checks are accepted.

Changing things

Each thing is edited on the tab that shows it: Checks, Environment and Survey each have an Edit in their heading. Saving a change to the checks or the environment (Save and run checks) runs the checks again at once, so a broken edit is found in minutes rather than by the next feature. The project's name, its repository and the branch features start from are edited on the Survey tab, which also holds Remove project. Removing a project leaves your repository untouched, and keeps the feature branches unless you tick the box to delete them.
