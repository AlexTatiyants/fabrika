Architecture is how the system runs: who uses it, which processes it's made of, and what it talks to outside the repository.

The map

Each box in the middle is a process (a server, a web app, a worker), and carries the subsystems that run in it. Around it are the people and systems that use it, and the outside services it uses. Select a box to open it.

How sure each part is shows in the line style: code confirmed it, the reader reported it in the files it names, or only named, in configuration or documentation.

The band along the bottom is build and tooling: subsystems where nothing runs in production, and outside systems that build, test or ship the code rather than serve it, such as CI or Docker for packaging. An outside system named only in build, CI and dependency files lands there, whatever the cartographer called it; one that running code names stays beside what runs.

Outside systems

Databases, other services, APIs, and the build and tooling systems, marked as such. Each says what it's used for, how many files name it, which subsystems reach it and which capabilities depend on it. Libraries, build tools and this repository's own name are listed apart as Not outside systems, though files mention them.

Endpoints

Every route the code serves, with the file that handles it, the process it runs in, who calls it, and whether a test reaches it. Filter by text, kind, caller, capability, or untested.
